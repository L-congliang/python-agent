# 故事：工具调用格式不匹配

## 一句话版本

mimo 模型输出了三种不同格式的工具调用，adapter 只支持一种，导致 60% 的工具调用被忽略，agent 无法执行任何操作。

## 问题描述

用真实 API（mimo v2.5pro）跑 benchmark 时，发现所有 file-edit 任务都失败（0% 通过率）。调试发现 tool_steps = 0——模型调用了工具，但 agent 没有识别到。

## 尝试过程

1. 最初假设：模型没有调用工具 → 但看原始输出，模型确实返回了工具调用
2. 深入调查：发现模型输出的格式和 adapter 的正则不匹配
3. 修复后发现：模型在不同 prompt 下会输出三种格式：
   - 格式 1: 旧 XML（tool_call 标签嵌套 tool 标签）
   - 格式 2: 新 JSON（tool 标签内是 JSON）
   - 格式 3: Anthropic 风格（function_xxx 标签）

## 解决方案

把 adapter 改成多格式兼容：按优先级依次尝试匹配三种格式。

## 学到的东西

1. 模型输出格式不固定 — 不同的 system prompt 可能触发不同格式
2. adapter 是关键桥梁 — 格式不匹配，整个 agent 就废了
3. benchmark 的价值 — 没有 benchmark，这个问题不会被发现
4. 调试方法 — 看原始输出 > 看解析结果 > 看执行结果，逐层排查

## 面试完整版

我在用真实 API 跑 benchmark 时发现一个 bug：file-edit 任务全部失败，但模型确实返回了工具调用。我逐层排查——先看 agent 的执行日志，发现 tool_steps = 0；再看模型的原始输出，发现工具调用确实存在；最后对比 adapter 的正则和模型的输出格式，发现格式不匹配。

深入调查后发现 mimo 模型会输出三种不同的工具调用格式。adapter 最初只支持一种，导致其他两种被当作普通文本忽略。

修复方案是让 adapter 兼容三种格式，按优先级依次尝试匹配。这个经历让我意识到：模型的输出格式不是固定的，适配层的设计必须考虑兼容性。
