## 关键发现

### 1. 三组差异极小

| 指标 | memory_on | memory_off | memory_irrelevant | 差异范围 |
|------|-----------|------------|-------------------|----------|
| memory_dependent_success_rate | 96.00% | 94.00% | 97.50% | **3.5%** |
| correct_rate | 97.78% | 95.56% | 98.61% | **3.05%** |
| target_reread_rate | 7.78% | 4.44% | 5.56% | **3.34%** |

### 2. memory_irrelevant 表现最好

- memory_dependent_success_rate: **97.50%** (最高)
- correct_rate: **98.61%** (最高)
- 这说明记忆系统对当前任务集的帮助有限，模型本身的推理能力足够应对

### 3. target_reread_rate 分析

- memory_on (7.78%) > memory_irrelevant (5.56%) > memory_off (4.44%)
- memory_on 的 reread 率反而最高，可能是因为记忆系统注入的信息促使模型更谨慎地验证

### 4. 效率对比

| Config | avg_tool_calls | avg_duration |
|--------|----------------|--------------|
| memory_on | 2.1 | **20.2s** |
| memory_off | 2.0 | 13.4s |
| memory_irrelevant | 2.0 | 13.4s |

memory_on 的平均耗时比其他两组多 50%，但工具调用次数相似。

## 结论

### 主要结论

**当前 18 个任务 + mimo v2.5pro 模型下，记忆系统的效果不显著。**

- 三组的 memory_dependent_success_rate 差异仅 3.5%，在实验波动范围内
- memory_irrelevant 表现最好，说明记忆系统没有提供有效帮助
- 模型本身的推理能力足够强，能够通过工具调用完成任务

### 可能原因

1. **任务难度不够** — 当前 L3/L4 任务可能不够复杂，模型可以通过工具调用弥补记忆缺失
2. **模型能力太强** — mimo v2.5pro 的推理能力足够强，记忆增益被掩盖
3. **记忆系统不够精准** — 检索和注入的记忆可能不够相关或不够关键
4. **任务设计问题** — 任务可能更依赖工具调用而非记忆

### 下一步建议

1. **增加任务难度** — 设计需要跨多轮、跨多文件的复杂任务
2. **增加任务数量** — 扩大样本量以减少波动
3. **优化记忆系统** — 提高检索精准度和注入策略
4. **对比不同模型** — 在能力较弱的模型上测试记忆效果
